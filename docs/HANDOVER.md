## 4. 規則の要点

出典は「2026 Ene-1 KV-40 統一規則書」（PDF 32 ページ）。**PDF は主催者の資料なのでリポジトリに入れていない**（チームが持っている）。PDF のページ番号は、印刷されたページ番号より 1 つ大きい。使ったページ：PDF 18〜21 ページ（印刷 17〜20。車両規則。21 ページにブレーカーの例の図）、25 ページ（印刷 24。会場図・コース図・セクター）、26 ページ（印刷 25。ELEVATION 図とカーブ半径）。

| 条文 | 決まり | このプロジェクトへの影響 |
|---|---|---|
| 第1章 第1条 | Div1 の乗員重量は 56kg 以上（DivNEXT は CFRP を使えない） | 総重量 70kg なら車は約 14kg。軽量化より空気抵抗のほうが効く |
| 第3章 車体サイズ | 全高 1,800mm 以下、全長 3,500mm 以下、全幅 1,700mm 以下、トレッド 380mm 以上、ホイルベース 1,000mm 以上 | 写真では全長が上限いっぱい |
| 第3章 第7条 1) | 動力源は指定の充電式単 3 × 40 本だけ。計器類は別電源を使ってよい | 20 直列 × 2 並列。電力計は USB モバイルバッテリーで動かす |
| 第7条 2) | 最初の走行のあとは充電できない | 3 回を 3800mAh で走る |
| 第7条 3) | 電池はブレーカーごと、工具なしで外せる（オフィシャルが保管する） | ブレーカーを電池ケースに入れ、D-5200 で切り離す（[WIRING](WIRING.md)） |

| 第9条 | キャパシタなどの蓄電装置は使えない | 電力計の電源を守る大きなコンデンサの案は、事務局に確かめてから |

| 第14条 1)・4) | 無線機は禁止。ただし WiFi などで車両の情報を受信するのはよい | ピットへの送信を作るなら WiFi で。TWELITE などが「無線機」に当たるかは事務局に確かめる |

## 7. ファームウェア

くわしい動きは [README](../README.md) の「表示」「ボタン」「故障への備え」「ログ」。ここでは要点と、決めた理由。

### 画面

```
V: 24.53V  I: 12.34A      電圧・電流（20A を超えたら OVER）
P: 303W  Q:  1234mAh      電力・積算 mAh（INA228 が読めない間は LAST Q）
TIME  12:34 32.5km/h      経過時間・速さ
REC LOG003.CSV     *      記録中のファイル（NO SD、INA!回数、ボタンの案内もここ）
```

### いちばん大事な要件と、その作り

**何が起きても、積算 mAh の記録と、いまの電流の表示を続ける**（PR #6）。

| 起きること | 作り |
|---|---|
| 電力計の電源が落ちる | EEPROM に 2 秒ごと（と起動直後すぐ）に積算・経過時間・距離を保存し、続きから数える（`RESTORED (mAh KEPT)`）。20 バイトの記録を 50 か所に順に書き、CRC16（MODBUS）で書きかけを見分ける。`EE_MAGIC` 0xE1A2。1 回の loop で 1 バイトずつ書く |
| Nano だけリセット | INA228 に設定が残っていれば積算を消さずに再開。経過時間と距離は `.noinit` の RAM から（`RESUMED (mAh KEPT)`） |
| INA228 が見つからない・読めない | 止まらない。最後に読めた積算を `LAST Q` で出し、つながるまで探す |
| INA228 の設定が消える | 検出して設定し直し、積算を引き継ぐ（`INA!回数`） |
| I2C が固まる | Wire のタイムアウト 3ms |
| 処理が固まる | ウォッチドッグ 8 秒（旧ブートローダの Nano では再起動を繰り返すので、Optiboot にするか `USE_WATCHDOG 0`） |
| LCD が化ける | 5 秒ごとに初期化コマンドを送り直す |
| SD が抜ける | 1 秒ごとの書き込みの確定のあとに CMD13 で確かめ、約 2 秒で `NO SD`。走行中に初期化し直さない（入れ直しても記録しない） |
| ボタンの線がショート | リセットは「3 秒以上押して離したとき」だけ。10 秒以上押したままなら無視（`BUTTON STUCK?`） |

### 主な設定（スケッチの先頭）

ピン：A4/A5 = I2C（INA228 0x40、LCD 0x3C〜0x3F を自動で探す）、D2 = ボタン、D3 = 速度センサー（INT1）、D10〜D13 = microSD（CS = D10）。

### 気をつけること

- 20A を超えた分は 20A として数えるので、積算が少なくなる（`OVER`）
- ファームウェアを書き換えると EEPROM の形が変わることがあるので、書き換えたら 3 秒長押しで 0 にしてから使う
- LCD の 4 行の順番（行の先頭アドレス 00h / 40h / 14h / 54h）は、実機で確かめていない
- `SPEED_MAX_KMH` は 90 だが、シミュレーションの最高速は 83〜86km/h（空気抵抗を減らすほど速くなる）。余裕が小さい（[12 章](#12-次にやること)）

## 10. 鈴鹿シミュレーション

ファイル：`tools/suzuka_sim/suzuka-sim.js`（モデル。UMD）、`cli.mjs`（走り方を比べる表と CSV）、`digitize_elevation.py`（大会資料の標高図を数値にする）。

### 10.1 モデルのしくみ

50ms ごとに次を計算する。

1. **出してよい速さ**：平らな所で保つ速さ（`cruiseKmh`、120 なら全開）と、シケイン（5095〜5167m、40km/h）の手前のブレーキ（2.5m/s²）
2. **かかる力**：空気抵抗 ½ρ·CdA·v²、転がり抵抗 Crr·m·g、坂 m·g·勾配（下りでは前に押す力になる）
3. **駆動の力**：ほしいタイヤの力から、モーターの電流と界磁の強さを決める。界磁は 1（特性図のまま）から `fieldMin` までの中で、いちばん大きな力が出るものを選ぶ。電池の電流は `maxCurrentA`（10A）まで、モーターの電流は `motorMaxA`（30A）まで
4. **モーター**：逆起電力定数 Ke = 24V ÷ 1780rpm = 0.1288 V·s/rad、回転数の下がり方から内部の電圧降下 0.1238Ω、銅損 0.08Ω、無負荷の損失 10W（摩擦の電流 0.417A）。界磁を k に弱めると Ke·k、銅損 ×(1 + 2.0·(1−k))、摩擦の電流 ÷k
5. **電池**：放電した割合から 1 本の開放電圧（表）× 20 − 電流 × 0.2Ω。1 本 0.95V で電流を絞る
6. **ブレーカー**：10A を超えた分 ((I/10)² − 1) を時間で積み、26.4 秒分たまると切れる（12A で 60 秒）。10A 以下では 30 秒ほどで冷える。切れたら止まり、60 秒後に入れ直す
7. **走り方**：全開・控えめ（電池の 80% を使う速さ）・**上りだけ増やす**（勾配が `boostGrade` より急な上りで、ブレーカーの熱が `boostHeatMax` より少ない間だけ `boostA` まで流す）・下りで絞る・下りで惰性
8. **惰性のとき**：モーターの引きずり（タイヤで約 0.53N）をかける（`motorDragWhenCoasting`）

コースのデータ：

- **標高**：特別規則の ELEVATION 図（PDF 26 ページ）を `digitize_elevation.py` で 50m ごとに読み取った値。1 周で同じ高さに戻すため、読み取りのずれ（1 周で 1.3m）を距離に比例して戻している。スクリプトで作り直すと、コードの値との差は最大 0.3m
- **カーブ**：同じ図の下の Curve Radius（破線の範囲と R の数字）を目で読んだ値（`CORNERS`）。ブレーキがシケインだけなので、いまはシケインの位置にしか効かない
- **区間の名前**（`SECTIONS`）：表示用。ホームストレート、1・2 コーナー、S 字、逆バンク、ダンロップ、デグナー、立体交差の下、ヘアピン、200R、スプーン、バックストレート、130R、シケイン、最終コーナー
- 参考：PDF 25 ページには公式のセクター（区間 1 = 1,658m、区間 2 = 936m、区間 3 = 2,130m、区間 4 = 1,084m）もある。まだ使っていない

ファームウェアとのつなぎ（`cli.mjs --firmware`）：シミュレーションの電流・電圧・車輪のパルスを host_sim のファームウェアに流し、電力計が書く CSV と LCD を確かめる。積算 mAh（10A 全開で 3393.2mAh）と距離（17.936km）がモデルと合った。

### 10.4 分かったこと

1. **壁は電池ではなくブレーカー**：どの走り方でも電池は 80〜90% しか使わない。10A × 24V ≒ 240W で力が頭打ちになる
2. **時間がかかるのは S 字から逆バンク、ダンロップへの上り**（標高差 約 34m、最大 約 6%）
3. **上りだけ 12A**（勾配 2% 以上で、ブレーカーの熱が 85% になるまで）で 10A 全開より 26 秒速い。使えるのは 1 周でほぼこの上り 1 回分（平らな所で 10A ちょうどを流している間は、熱が減らないため）。平らな所を 10A より下げて冷ます、ブレーカーの冷え方を遅くする、は効かなかった
4. **12A のまま全開は、毎周ブレーカーが切れて完走できない**。規則では完走できないと次のアタックに出られないので、絶対に避ける
5. **目標の 6:15 × 3（18:45）**には、空気抵抗・転がり抵抗をもう一段下げ（CdA 0.035〜0.04、Crr 0.0025）、**さらに上りで 10A を超えて流す**必要がある。いまのブレーカーの見立て（12A で 1 分）と上りだけ 12A では、CdA 0.035・Crr 0.0025 でも 19:00 で 15 秒足りない。ブレーカーの切れ方しだいで変わる
6. **可変界磁**：弱め始めるのは「10A を流しきれなくなる速さ」から。電池 26V で 70.6km/h、24V で 64.9km/h、22V で 59.2km/h、20V で 53.4km/h（回を追うごとに早くなる）。弱めているのは電流を流している時間の 27%（バックストレート、ホームストレート、130R、立体交差の下など速い区間だけ）。可変界磁があると合計 32 秒速い
7. **ギアは 60T〜72T でタイムはほぼ同じ**（78T だと 8〜10 秒遅い）。ただし**ダンロップの上り（約 6%）の途中で止まると、60T では再発進できないおそれ**：タイヤで約 43N 要るが、60T でモーター 30A なら 35.5N。66T・72T なら 35A、78T なら 30A で足りる（60T なら 40A）。コントローラーの電流の上限しだい。全開で勢いをつけて入れば登り切れる（最低 約 17km/h）ので、前の車に詰まったときの話
8. **下りでアクセルを戻すと遅くなる**：鈴鹿の下りの多くは −1% 前後と緩やかで、惰性にすると重力が転がり抵抗と空気抵抗にほとんど食われる
9. **下り坂の重力は入っている**：3 周分の坂の仕事の合計はほぼ 0（上りで使った分を下りで取り戻している）
10. **ブレーキをシケインだけにした**ことで、ブレーキで捨てるエネルギーは 9.1Wh から 3.6Wh に減り、1 周 約 22 秒速くなった
11. **空気抵抗がいちばん効く**：CdA が 0.005 下がるごとに合計 約 27 秒（1 周 約 9 秒）。写真からは、車体の下からはみ出して回る前輪を覆うと CdA が 0.003〜0.006 下がるかもしれない（合計 15〜30 秒。写真からの推定）。パネルの継ぎ目のテープ、キャノピーと窓の縁の段差も平らにするとよい。細く絞った尾部は良い形

### 10.5 モデルの限界

- 空気抵抗・転がり抵抗・電池の容量・コントローラーの効率と電流の上限・可変界磁の切り替わり方は**見積もり**
- ブレーカーは「定格を超えた分の 2 乗を時間で積む」近似で、実物の動作特性曲線ではない
- アタックの間の電池の電圧の回復を入れていない（実際の 2・3 回目は、もう少し速いはず）。電池とブレーカーの温度も入れていない
- 風、タイヤの滑り、ドライバーの走行ラインの違いは入れていない
- 標高は図の読み取りなので、誤差がある（コードの値とスクリプトの差で最大 0.3m）

### 10.6 使い方

```bash
node tools/suzuka_sim/cli.mjs                                  # 走り方を比べる表と CSV（tools/suzuka_sim/out/<走り方>/）
node tools/suzuka_sim/cli.mjs --firmware                       # さらにファームウェアに流して、out/firmware/ に電力計の記録
node tools/suzuka_sim/cli.mjs --set cdA=0.04 --set crr=0.0025  # 値を変える（DEFAULTS の名前）
```

`suzuka-sim.js` が外に出しているもの：`simulate`（走行の計算）、`strategies`（4 つの走り方）、`optimizeBoost`（上りだけ増やす組み合わせを探す）、`findCruise`（電池の割合を使い切る速さ）、`forLapTime`（目標タイムに届く速さ）、`maxCdAFor`（目標タイムに必要な CdA）、`toCsv`・`toDetailCsv`（CSV）、`DEFAULTS`・`MOTOR`・`ELEVATION`・`SECTIONS`・`CORNERS` など。

詳しい CSV（`detail.csv`）の列：`time_s, attack, phase, lap_distance_m, section, elevation_m, grade_pct, speed_kmh, voltage_V, current_A, power_W, charge_mAh, motor_current_A, field_pct, breaker_heat_pct`（Excel 用に BOM 付き）。

## 11. 答えを待っている質問

チームに聞いたが、まだ答えをもらっていないもの・確かめたいもの。上ほど大事。

1. **速いときにアクセルを戻したら、モーターはどうなるか**（2 回聞いて未回答）：ワンウェイクラッチで切り離されるか、可変界磁が弱いまま保たれるか。逆起電力が電池の電圧を超えると、コントローラーの中のダイオードを通って回生ブレーキがかかり、電池に充電されるおそれがある（第7条 6）。下りでの減速にも関わる。シミュレーションの `motorDragWhenCoasting` もこれで決まる
2. **コントローラーがモーターに流せる電流の上限**（30A は仮定）：ダンロップの上りで止まったときに再発進できるかが決まる（[10.4 の 7](#104-分かったこと)）。コントローラーの型番か、設定できる上限
3. **ブレーカーの型番と動作特性曲線**：12A で 1 分は見立て。曲線が分かれば `breakerHeatS`・`breakerCoolS` を合わせ、`optimizeBoost` で上りに流してよい電流と時間を決められる
4. **M1048 の可変界磁の切り替わり方**：何 rpm で切り替わるか、どこまで弱まるか、少しずつか段階的か。ミツバの資料かサポートで分かるかもしれない
5. **空気抵抗と転がり抵抗の実測**：速度センサーで、惰性で速さが落ちる様子か、2〜3 通りの一定の速さでの電力を記録すれば計算できる
6. **指定の電池の型番と容量**（大会のブルテンで公示）：シミュレーションの 1900mAh は仮
7. **実車の Nano のブートローダ**：Optiboot か旧ブートローダか（旧ならウォッチドッグで再起動を繰り返す）
8. **LCD モジュールと microSD モジュールの端子の並び**：配線図では働きの名前で書いた（基板の印字で確かめる）

## 14. 大会の日の注意

- **新しいレース（大会）の前に、ボタンを 3 秒長押しして積算を 0 にする**。電源を入れ直しても 0 にはならない
- 3 回のアタックは同じ電池なので、アタックの間は 0 にしない（電力計の電源を切っても、続きから数える）
- ファームウェアを書き換えたら、長押しで 0 にしてから使う
- microSD は電源を入れる前に入れる（走行中に入れ直しても記録しない）
- 電力計は計器用の別電源（USB モバイルバッテリー）で動かす（第10条）。車検で「動力と別系統」を説明できるようにしておく（[WIRING の 5 章](WIRING.md#5-規則との対応2026-kv-40-統一規則特別規則)）
- 表示の意味と困ったときは [TROUBLESHOOTING](TROUBLESHOOTING.md)

## 15. 用語

| 言葉 | 意味 |
|---|---|
| mAh | 電池から出した電気の量（ミリアンペア時）。積算 mAh |
| CdA | 空気抵抗の大きさ（空気抵抗係数 × 前面投影面積、m²）。小さいほど速い |
| Crr | 転がり抵抗係数。タイヤと路面で決まる |
| 可変界磁 | モーターの磁力を弱めて、高い回転まで回せるようにするしくみ |
| 熱動式ブレーカー | 電流の熱で切れるブレーカー。少しの超過なら時間をおいて切れる |
| 動作特性曲線 | ブレーカーが「何 A で何秒で切れるか」のグラフ |
| CI | push のたびにテストを自動で回すしくみ（GitHub Actions） |
| PR | プルリクエスト。ブランチの変更を main に取り込む前に確かめる単位 |
| host_sim | スケッチを PC 用にコンパイルして動かすテスト |
| avr_emu | 実機と同じ .hex を、Nano のマイコンのエミュレーターで動かすテスト |
| EEPROM | 電源を切っても消えない Nano のメモリ（1KB）。積算の保存に使う |
| `.noinit` | リセットしても消えない RAM の領域。Nano だけのリセットのときに経過時間と距離を残す |
| ウォッチドッグ | 処理が固まったら Nano をリセットするしくみ |
