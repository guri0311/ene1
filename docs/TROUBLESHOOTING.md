# トラブルシューティング

実機で動かないときに、症状から原因を探すための表。まず USB シリアル（115200bps、`SERIAL_DEBUG 1`）の起動メッセージを見ると、どこで止まっているかが分かる。

## 1. 起動メッセージの読み方

正常なとき:

```
Ene-1 PowerMeter
I2C scan: 0x3C(LCD?) 0x40(INA228)
LCD: 0x3C OK
INA228: configured
SHUNT_CAL=3500
SD: LOG000.CSV
time_s,voltage_V,current_A,power_W,charge_mAh
```

| 行 | 見るところ |
|---|---|
| `I2C scan:` | I2C で応答した部品のアドレス。`0x40` が INA228、`0x3C`〜`0x3F` のどれかが LCD。何も出なければ（`none`）I2C 配線全体の問題 |
| `LCD:` | 使う LCD のアドレス。`no ACK` なら LCD が応答していない |
| `INA228:` | `configured` = 電源投入から設定した（保存された積算なし）。`resumed (mAh kept)` = Nano だけがリセットされ、積算を引き継いだ。`restored (mAh kept)` = 電源が全部落ちたあと、EEPROM に保存した積算から続けた。`no response` = INA228 が応答しない（探し続ける） |
| `SD:` | 記録中のファイル名、または `NO SD` |
| `# RAM min free:` | 30 秒ごと。起動してから一番少なかった空き RAM。100 バイトを切るようなら要注意 |

## 2. 症状別

### LCD

| 症状 | 考えられる原因 | 確認・対策 |
|---|---|---|
| バックライトが点かない | BL+ / BL− の配線 | BL+（6 番）に 5V、BL−（7 番）に GND。抵抗は基板に載っている |
| バックライトは点くが何も表示されない | I2C が届いていない | シリアルの `I2C scan` に 0x3C〜0x3F が出るか。出なければ SDA / SCL の入れ違い、GND 未接続、プルアップ抵抗なし |
| 同上（スキャンには出る） | 電源電圧が低い | LCD の電源は 5V 用で、コントラスト調整ピン（V0）は未接続。Nano を USB 給電すると 5V ピンはダイオード分下がって 4.6V 前後になり、特に低温では文字が薄くなる。5V ピンの電圧を測る |
| 4 行の順番が入れ替わる | 行の先頭アドレスの違い | `LCD_ROW_ADDR`（00h / 40h / 14h / 54h）を入れ替える |
| 走行中に文字化けする | モーターのノイズ | 5 秒以内に自動で直る。直らない・頻発するなら I2C 線を短く、より線にし、モーター配線から離す。プルアップを 2.2kΩ に下げる（データシートの推奨値） |

### INA228（電圧・電流）

| 症状 | 考えられる原因 | 確認・対策 |
|---|---|---|
| 起動時に `INA228 NOT FOUND` / `ID=0000 RETRYING` | INA228 が応答しない | `I2C scan` に 0x40 が出るか。モジュールの電源（VS）、Nano と INA228 の GND 共通、SDA / SCL。止まらずに探し続けるので、つながれば表示が戻る |
| 起動時に `INA228 NOT FOUND` / `ID=` が 0000 以外 | 0x40 に別の部品がいる | モジュールの A0 / A1 の設定 |
| `INA228 CONFIG ERROR` | 書いた設定が読み戻せない | I2C の通信が不安定。配線長・プルアップ・GND |
| 電圧が 0V | バス電圧の入力（V+）が未接続 | V+ を電池＋に。V− が電池− |
| 電流の符号が逆（走ると負） | ISENSE+ / ISENSE− が逆 | ISENSE+ を電池側、ISENSE− をモーターコントローラー側 |
| 1 行目の電流が `OVER` になる | 20A を超えている | ローレンジ（`INA_ADCRANGE = 1`、±40.96mV）で 2mΩ だと 20.48A までしか測れず、`MAX_CURRENT_A`（20A）で頭打ちになる。その間は mAh も少なく数える。頻繁に出るなら `INA_ADCRANGE = 0` と `MAX_CURRENT_A = 81.92` に戻す（分解能は 1/4 になる） |
| 電流が大きくふらつく | モーターコントローラーの PWM | 16 回平均で約 18ms ごとに更新している（記録は 50ms ごと）。記録間隔を 100ms 以上にして `INA_AVG` を 3（64 回平均）にするか、データシートに従い入力に RC フィルタを入れる。積算 mAh はふらつきの影響を受けない |
| 電圧が負荷で大きく下がって見える | INA228 の GND をモーター電流の流れる線の途中につないでいる | INA228 の GND は電池−端子に専用の線で直接つなぐ |
| 3 行目に `INA!1` などが出る | INA228 が走行中に設定を失った（電源の瞬断） | 積算は引き継いでいる。INA228 の電源線・コネクタの接触を確認 |
| `INA228 I2C ERROR` | 走行中に INA228 が応答しなくなった | 配線の抜け・接触不良。戻れば自動で復帰する |

### 積算 mAh・時間

| 症状 | 考えられる原因 | 確認・対策 |
|---|---|---|
| 書き込み後や電源を入れ直しても mAh が 0 に戻らない | 仕様（積算を 0 にするのはボタンの長押しだけ。電源を入れ直しても EEPROM に保存した値から続ける） | ボタンを 3 秒以上押して離す |
| 2 行目が `LAST    Q:  1234mAh` になる | INA228 が読めない（1 行目は `INA228 I2C ERROR`） | 最後に読めた積算を出している。INA228 の中では積算が続いているので、配線が戻れば正しい値に戻る。INA228 の配線・コネクタを確認 |
| 電源を入れ直したら mAh が少し減った | 積算の保存は 2 秒ごと | 最後の保存から電源が落ちるまで（最大 2 秒）と、電源が落ちていた間の分は数えられない |
| mAh が減る | 電流が負（回生、または ISENSE の逆接続） | 1 行目の電流の符号 |
| 経過時間が公式タイムとずれる | Nano のクロック誤差（セラミック発振子で ±0.5% 程度、1 時間で最大 18 秒） | mAh は INA228 内部の時計で積算しているので影響しない。時間は目安として使う |

### SD カード

| 症状 | 考えられる原因 | 確認・対策 |
|---|---|---|
| 常に `NO SD` | カードの形式 | SD ライブラリは FAT16 / FAT32 のみ。64GB 以上（SDXC、exFAT）は使えない。32GB 以下を FAT32 でフォーマット |
| 同上 | 配線 | CS = D10、MOSI = D11、MISO = D12、SCK = D13。モジュールの電源は 5V |
| 走行中に `NO SD` になる | カードの接触・抜け | カードが応答しなくなると約 2 秒で `NO SD` になる。SD の初期化は起動時だけなので、走行中は記録が止まる（表示と積算は続く）。カードを挿し直して Nano のリセットボタンを押すと記録が再開する。INA228 の電源が切れていなければ積算は引き継がれる |
| 書き込みの遅いカードで `NO SD` になる | 1 回の書き込みが約 0.6 秒を超えた（SD ライブラリのタイムアウト） | 規格上の上限は 0.25 秒で、その範囲なら問題ない。古いカードや偽物のカードは交換する |
| PC の検査ツールが「空き容量の情報が違う」と言う | SD ライブラリが FAT32 の空き容量の目安（FSInfo）を更新しない | 目安の値だけの差で、ファイルの中身には影響しない。そのまま使ってよい |
| CSV の時刻が 1 秒ごとに数百 ms 飛ぶ | 書き込みの遅い SD カード（書き込み確定のたびに待たされる） | 表示と積算は止まらない。速いカード（Class 10 / UHS など）に替える。`LOG_FLUSH_MS` を大きくすると飛ぶ回数が減る |
| 最後の 1 秒ほどが記録されていない | 1 秒ごとに書き込みを確定しているため | 電源断で最大 1 秒分が残らない。`LOG_FLUSH_MS` を小さくすると早く確定するが、SD への書き込みが増える |

### ボタン・再起動

| 症状 | 考えられる原因 | 確認・対策 |
|---|---|---|
| 4 行目に `BUTTON STUCK?` | ボタンが 10 秒以上押されたまま（配線のショート） | ボタン線の挟み込み・被覆の破れ。この状態ではリセットは起きない |
| 4 行目に `RELEASE=RESET mAh` | 3 秒以上押している | 離すと積算と時間が 0 になる。やめたいときは 10 秒以上押し続けてから離す |
| 再起動を繰り返す | モバイルバッテリーの自動オフ・電圧低下 | 低電流モードのあるモバイルバッテリーを使う |
| 表示が止まる（TIME が進まない） | 処理が固まった。または旧ブートローダの Nano でウォッチドッグが働き、再起動を繰り返している | Optiboot の Nano なら 8〜12 秒で自動的に再開する。旧ブートローダの Nano（書き込みに「Old Bootloader」が必要なもの）は電源を入れ直すまで止まったままなので、Optiboot を書き込むか `USE_WATCHDOG 0` にする。走行中は TIME が 1 秒ごとに進んでいるかで動作を確かめられる |

## 3. 実機バイナリのエミュレーターテスト

実機に書き込むのと同じ .hex を ATmega328P エミュレーターで動かす。Wire・SD ライブラリの実際の動き、AVR の整数の幅、RAM とスタックの実際の使用量、ウォッチドッグ、ブートローダ（Optiboot・旧ブートローダ）まで確かめられる。スケッチを変えたら実行する（約 6 分）。

```bash
cd test/avr_emu && npm install
```

```bash
cd test/avr_emu && node run.mjs
```

シナリオ名の一部を付けると、そのシナリオだけ実行する（例: `node run.mjs ボタン`）。

確認している内容: 起動表示とシリアル出力、測定と表示、CSV の中身と 50ms 刻み・行の抜けなし、FAT の整合性、逆電流と OVER、ボタン（3 秒未満・3 秒以上・押しっぱなし・チャタリング・リセット後の積算再開）、SD の抜き差しと検出時間、SD なし起動、書き込みの遅いカード、ログ 300 個からの起動、記録中の電源断、INA228 の瞬断・配線外れ・起動時になし（探し続ける）、電源断からの EEPROM による再開（ばらばらの時刻に 6 回）・積算リセット後の電源断、I2C の固まり、LCD のノイズ・アドレス自動検出・LCD なし、Nano のリセットと電源の入れ直し、ハングからのウォッチドッグ復帰（ブートローダなし・Optiboot・旧ブートローダ）、10 分の長時間動作と RAM の実測、`SERIAL_DEBUG 0` 版。

## 4. PC 上のシミュレーションテスト

INA228 と LCD（RW1063）をデータシートどおりにモデル化し、スケッチを PC 用にコンパイルして動かすテスト。エミュレーターより速い。

```bash
bash test/host_sim/run_tests.sh
```

メモリ破壊・未定義動作の検査付き:

```bash
SIM_SANITIZE=1 bash test/host_sim/run_tests.sh
```

確認している内容: 表示と記録、回生、ボタン（3 秒未満・3 秒以上・押しっぱなし・リセット後の積算再開）、SD の抜き差し、SD なし起動、INA228 の瞬断・配線外れ、LCD のノイズ、Nano だけのリセット、INA228 なし、LCD アドレスの自動検出、20A 超え（OVER 表示）、2 時間の長時間動作、SD にログが大量にあるときの起動時間、LCD のタイミング違反、ウォッチドッグの間隔。

実機でしか分からないこと（実際のノイズ、PWM の影響、LCD の行の並び、カードごとの細かな癖、部品モデルとの差）はどちらのテストでも確認できない。
